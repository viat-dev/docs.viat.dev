# 生产加固与安全恢复

本清单面向部署/安全管理员与项目 Owner。**不能仅因文档列出就执行真实
修改**:所有命令/配置示例未执行;生产密钥轮换、账号重置、网络变更与删除
都要明确批准。准确解析/默认见[安全配置](../configuration/security.md)。

## 明确信任边界

Viat 执行开发者代码。不同 UID、清空环境与资源代理能**减少**暴露,但
**不保证**恶意代码不能联网、耗尽资源或读取所有已授资源的凭据——1.1.0
部分数据库/缓存/AMQP/S3 对象仍向脚本投射凭据。因此:

- 代码权限只开放给可信作者,且限于其可访问的资源;互不信任的租户/负载
  用**独立实例、账号与网络**。
- 业务账号按最小权限配置——宽泛的生产凭据会放大脚本权限,日志屏蔽消除
  不了这一点。
- 保留内存/PID 限制、系统调用约束与主机补丁;不把 Docker socket、宿主
  根、密钥目录或无关备份挂进脚本可见的树。
- 出口用网络策略限制。`VIAT_OUTBOUND_DENY_PRIVATE` 只是选定保存路径的
  主机检查——**不是**完整 DNS 重绑定防护,更不是任意代码防火墙。
- Rust 编译能力 = builder 上的**特权代码执行**:依赖/build script 可在
  worker 降权之前执行。

## 向用户开放前

1. 固定批准的 1.1.0 镜像/摘要,分别记录服务端与客户端版本;受支持的主机
   与容器运行时并保持补丁——旧 bullseye 镜像只是过渡,不是长期安全建议。
2. 设置独立强主密钥与 JWT;原主密钥独立保管并演练获取;确认启动无开发
   JWT 警告——**二进制不会因危险默认值拒绝启动**。
3. 非明确需要就关闭公开注册;移除初始凭据前确认仍有可用 Owner;修改
   bootstrap 密码**不重置**已有账号。
4. 限制管理入口:HTTPS + 可信 `VIAT_PUBLIC_URL`;只有受控代理后才信任
   转发头。API-only 部署可关控制台/文档,但 API 本身仍要认证/网络策略。
5. 查 worker 身份日志:Docker 下父进程 root 启动 10001/10001 子进程;
   账号缺失、UID 非法或降权关闭会让 worker 与服务器**同身份**;父进程改
   非特权不会神奇地保留不同的子 UID。
6. 限制文件/监听/SQLite 根,只挂批准目录;`VIAT_WORKER_DATA_DIRS` 递归
   改属主——不可指向宽泛宿主目录或平台 spool。
7. 先准备登记与恢复再强制 MFA;PAT 用最小 scope;审核实际的
   **operator/developer/admin/owner** 项目角色——平台角色与项目成员资格
   不同。
8. 指标用随机 token 与专用网络;外部日志/追踪/负载都按敏感数据保护;
   私有 CA 的问题**不能**靠关闭 TLS 验证解决。
9. 一致备份平台库、主密钥、外部秘密/业务库/文件,并演练
   [隔离恢复](backup-restore.md)。

## 凭据与证书变更

| 对象 | 运维方式 | 风险 |
| --- | --- | --- |
| 平台 JWT | 批准后**同步重启所有节点**,再让受影响方重新登录/签发 | 已签令牌失效;节点不一致会间歇失败 |
| 主密钥 | 保留原值;重加密/迁移须单独设计验证流程 | 只替换环境会使 AES 密文不可用;**没有自动轮换** |
| 资源凭据 | 经授权控制台/API 修改;受控验证并协调 live/published 行为 | 部分脚本对象可读凭据;旧凭据还要在 provider 侧撤销 |
| Vault/AWS 身份 | 轮换受限身份;保留历史引用的读权限;按需重启静态客户端 | Viat 不续期 Vault token;换后端不迁移 blob |
| TLS 证书 | 原子替换匹配的 PEM 对;内置 TLS 每 60 秒检查 mtime | 失败保留旧证书;期限/实际指纹要外部监控 |
| CLI/MCP 会话/PAT | 用真实认证控制撤销**服务端**凭据;按政策移除本地副本 | 删 `.viat/config.yaml` 不证明服务端凭据已撤销 |

> [!WARNING]
> 不要用宽泛 passthrough 规则传秘密:禁止表只保护特定核心名与
> Cargo/SSH 前缀,**不识别所有应用秘密**;默认透传的包源命名空间里的
> token 也能被 worker 读取。用无害标记验证规则——不要打印真实秘密。

## 怀疑泄露时

1. 记录 UTC 区间、身份/项目、请求/运行 ID、节点与镜像;私密保留日志/
   审计/provider 事件——**不要把秘密复制进工单**。
2. 按事故计划隔离恶意入口、生产者与节点;取消不回滚外部提交;杀掉全部
   容器可能丢失易失证据。
3. 在正确的控制面撤销会话/PAT/资源/provider 凭据;检查权限、发布快照、
   共享模块、告警目标与绑定——**旧备份可复活队列/凭据**。
4. 结合[控制面/业务审计](audit.md)、provider 日志与资源权限判断暴露
   面向:匿名请求、部分读取与尽力日志有明确缺口——**没记录不等于没
   行为**。
5. 从批准产物重建、在隔离环境恢复——不盲拷受污染的缓存/二进制,不重放
   副作用。
6. 用已知夹具验证恢复:worker 身份、激活、探针与外部监控;分阶段开放,
   记录未测依赖与根因。

## 已知保证边界

- 业务 PostgreSQL 资源的 `ssl` 当前被忽略;MySQL `ssl=true` 为
  Preferred(可回退)。强制传输要靠**经验证的数据库/代理/网络边界**并
  实际验证——资源保存成功不是证据,见[数据库](../configuration/database.md)。
- 进程内告警在进程/数据库/出口宕机时无法保证通知;provider 接纳不代表
  收件人收到。
- 审计表不独立防御 DBA,不是 WORM。
- 租约/锁/幂等不是笼统的 exactly-once/HA。

按风险与合规需求明确补偿控制。
