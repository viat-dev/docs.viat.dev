# 保留、历史与安全删除

保留配置由主机运维修改,并且会**不可逆删除数据**。项目角色不能提高部署
保留。缩短任何期限前:取得数据负责人/合规批准 → 导出必要证据 → 验证可
恢复备份。所有示例未执行,本页不授权运行清理。

## 默认生命周期

| 数据 | 默认 | 实际清理边界 |
| --- | --- | --- |
| 执行摘要 | 90 天 | 按创建时间批删;工作流子行随父级**级联删除** |
| PostgreSQL stdout/stderr/structured 行 | 14 天 | 删除整个旧**月分区**——不是精确逐行 14 天 TTL |
| 执行/工作流 I/O | 14 天 | 独立清空负载;摘要继续保留 |
| 已结束异步任务/结果 | 7 天 | 已结束行;未来排队任务不按此清理 |
| 聊天消息账本 | 90 天 | 消息历史行 |
| 聊天 peer context | 180 天**无活动** | 按最后活动,不是账号创建时间 |
| 控制面审计 | 365 天 | 平台 audit_logs,不是外部业务审计 |
| 文件读取审计 | 90 天 | 平台访问行 |
| 幂等键/已存响应 | 24 小时 | 去重与重试响应窗口 |
| 脚本旧版本 | 50 个替代版本(范围 1..1000) | 编辑时按**每脚本数量**裁剪,不是天数 |
| 发布 revision | 20 个 | 发布时裁剪;准确变量名 `VIAT_PUBLISH_REVIAT_KEEP` |

类型、零值与作用域见[完整保留变量](../configuration/observability.md)。
没有通用的"0 = 永久保留":**0 天可能在下次清理删掉几乎所有旧数据**;
间隔 0 虽可解析但不能用于定时器。法律保全用批准的外部证据流程——不要
猜"无限值"。

## 周期与粒度

- 默认每 24 小时清理。启动会维护当前与未来五个月的 PostgreSQL 行日志
  分区;**破坏性清理等完整一个周期**,不是每次启动立即清空。每阶段失败
  记录后继续;多实例协调集群任务但依赖幂等处理——不是不可变 exactly-once。
- 与截止日相交的**整月分区**必须保留,所以行日志可能比配置天数更久。
  负载可能早于摘要消失——payload 为 null 不表示原请求为空。执行摘要删除
  会连带删除其工作流步骤。PostgreSQL DELETE 后的空间复用/文件缩小由
  vacuum/存储管理决定,**不保证**立即返还给操作系统。
- 关闭 `VIAT_RETENTION_ENABLED` 会**同时**停掉该循环承担的分区维护与
  OAuth/session/ticket/MFA/登录失败等过期清理——没有替代维护时,不能当
  成"安全的无限保留"。上传暂存等专门清理独立。**不要**靠手工删活跃分区
  或 truncate 日志父表来"解决"磁盘满。

## 规划与应用

1. 盘点:PostgreSQL、ClickHouse/Loki、业务库、对象存储、容器日志、备份
   与导出——**删平台行不会删除外部副本**。
2. 为每类定义批准的最短/最长保留,考虑聊天/负载的个人信息、审计证据、
   以及客户端幂等重试窗口。
3. **降低前**导出证据并记录备份恢复点;清理后的快照找不回已删数据。
4. 修改部署变量(Compose 须显式传入),按维护计划重启。**更小的值会作用
   于下次清理时已超龄的历史行**——不只是对新数据的策略。
5. 监控清理日志与数据库磁盘/行数/分区趋势;排查权限、锁、DDL、存储错误
   ——进程健康不表示清理成功。
6. 抽查新旧记录与外部存储,保留批准记录;临时导出文件按证据政策处理。

以下为**未执行的策略示例**,不是通用建议:

```dotenv
VIAT_RETENTION_EXECUTION_DAYS=90
VIAT_RETENTION_PAYLOAD_DAYS=7
VIAT_RETENTION_LINE_DAYS=14
VIAT_RETENTION_AUDIT_DAYS=365
VIAT_RETENTION_IDEMPOTENCY_HOURS=24
VIAT_RETENTION_INTERVAL_HOURS=24
```

两个连锁反应:缩短幂等窗口后,旧键/响应被删,**迟到的重试可能重新执行**;
缩短异步结果期限后,客户端可能取不到完成结果。客户端行为要与窗口一致;
需长期保存的输出写进持久业务存储。

## 外部系统与误删恢复

- ClickHouse/Loki TTL、业务库审计、S3 生命周期/版本、文件字节、容器日志
  与备份都是**运维自行制定**的策略。外部秘密可能在资源修改后保留历史
  值——与数据库引用的生命周期协调。Rust 共享产物 GC 默认关闭:未掌握完整
  live-set 时,不可跨混合架构/工具链"安全清理"。
- 误缩短期限后再调高**找不回数据**。按事故批准控制停止进一步破坏性清理
  → 保留现场 → 按[备份恢复](backup-restore.md)恢复到**隔离环境** →
  经审阅只协调需要的数据。直接用旧库替换生产会丢失新写入,还可能复活
  已撤销的凭据或有副作用的排队任务。
