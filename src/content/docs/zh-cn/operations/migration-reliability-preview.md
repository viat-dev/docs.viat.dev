本文说明开发中的修复，**不是 1.3.0 已发布行为，也不改变 stable 手册的版本承诺**。使用前确认 CLI、客户端和发布脚本包含相应修复；发布后的正式参考需随新契约包更新。当前稳定版的边界见 [CLI 同步](../cli/sync.md)、[Widget](../clients/widgets.md) 和[客户端安装](../installation/clients.md)。

## 密钥包迁移

密钥导出仍要求源项目的相应权限；密钥包导入仍受目标项目的创建、编辑及 authorizer 管理权限约束。这些修复不会授予额外权限，也不会把导入变成一个可整体回滚的事务。

- 合法的可选密钥 `null` 会被保留。例如普通 S3 长期凭据没有 `session_token`，HTTP Bearer 认证不需要用户名与密码。它们不再让整个新资源被错误跳过。
- 不存在的密钥字段仍视为缺失；`cloud_api` 的密钥字段也保留合法的 `{"$secret":"name"}` 引用。其他无效值形状会拒绝处理，而不是猜测或打印其值。必填字段依然受服务端资源类型校验约束。
- 默认保留目标上已有的 OIDC 与 social authorizer，包括其配置和凭据，避免将源环境 `client_id` 与目标环境 `client_secret` 混用。当前配置不能证明不存在存量密钥：委托型 Alipay 关闭手机号采集后仍可能保留 AES 密钥，因此也需要这层保护。
- 新增导入选项 `--update-authorizers`，默认关闭。它单独授权覆盖上述已有 authorizer；密钥包内必须有源配置所需的完整可用凭据，并与配置一起更新。覆盖已有对象时，源配置合法地不需要自身凭据也必须携带密钥信封中的显式 `null`，不能从缺少信封推断“没有密钥”；新建无自身凭据的委托型对象不受此额外要求。完整替换与旧服务器拒绝规则见[凭据替换](authorizer-credentials-preview.md)。可见配置未变但密钥变化时，也不能漏掉凭据更新。缺少必需凭据时不会只覆盖配置。
- `--update-resources` 仍只控制已有资源，不扩大到 authorizer。普通仓库 `push` 不改变为上述导入保留策略。
- `--only meta --with-secrets` 可以只携带元数据及所选 authorizer 的密钥；不包含资源时，缺少 `resources/` 被视为空集合。脚本限定导出也不会因此夹带其他对象的凭据。
- 限定范围导出的 `viat.yaml` 会携带 `bundle_only` 列表。未选择 meta 时，只附带导入必需的项目 slug/name 和范围标记，不读取其他元数据。新版 import 默认沿用该范围；显式 `--only` 只能选择其中的子集，越界会在读取密钥或远端修改之前拒绝。`--as` 不丢失该标记，`--prune` 也不能删除未导出种类的对象。
- 无范围标记的旧包维持原有导入语义。**限定包请使用包含本修复的新版 CLI 导入**；旧 CLI 不识别范围标记，不能依靠它保护未导出的对象。
- 范围标记只限制同步阶段，不改变 `--publish` 的项目级发布语义；它不是局部发布或跨资产事务保证。

### 并发修改与输出

带密钥导出会在读取配置和密钥前后，对包实际包含的资源及 authorizer 检查对象 ID 和更新时间。发现更新、删除、同名重建或缺少必要版本信息时，导出拒绝成功封装，提示重试；不会输出一个宣称成功但配置与密钥版本不匹配的包。这是保守的一致性检查，不是全项目数据库快照，也不保证其他资产的跨对象事务一致性。

版本比较为每份列表建立一次身份索引，不再为每个选中对象扫描整个列表。范围内重名仍拒绝，范围外缺少版本或重复身份不会阻断选定对象；不同目录下同名资源仍按完整路径区分。这个优化不减少前后两次版本读取，也不放宽 ID/更新时间检查。

一次性密钥只在归档成功后输出，并位于 stdout 最后一行。密钥仍只应通过 stdin 交给导入命令，不应出现在命令行参数、日志、工单或仓库中。归档失败不能被当成成功导出。包与密钥应分别保管；完成隔离验证后清理不再需要的副本。

### 验证与恢复

先使用隔离目标项目验证普通 S3、HTTP Bearer、同名 OIDC authorizer 的导入结果；默认保留与显式覆盖应分别验证。检查导入汇总中保留或缺失的对象，再决定是否发布，不要将“导入完成”视为所有凭据都已迁移。导出提示对象变化时，等更新结束后重新导出；不建议绕过版本检查。

## 旧 Widget 自动恢复

升级前本地绑定没有 `bundle/environment` 时，自动维护使用当前 App 的 bundle 标识和构建环境申请新订阅，而不是向服务器提交空值。部署仍必须已有匹配的 APNs profile；修复不创建或猜测 Apple 凭据。

首次创建失败会保留旧绑定的重试意图，后续前台维护可再次尝试；恢复不依赖该实例当时正处于选中状态。只有匹配当前身份的新订阅成功保存后才替换旧绑定。退出登录、显式禁用和已知身份不匹配的隔离规则不放宽。

### 已知身份变化后的重试

已有非空身份与当前 App 的 bundle 或 APNs 环境不匹配时，不采用保留旧密钥的 legacy 例外。客户端先退休旧密钥和显示，在同一次经校验的安全存储写入中保存**不含密钥**的修复意图，绑定实例、部署、项目和新 epoch。创建失败后，前台维护可重试；进程重启也能恢复这个意图。它只代表此前已启用的订阅，不会因为某实例没有绑定就自动启用推送。

显示退休失败时，下一轮必须先重试该屏障，不能直接申请新订阅。密钥退休无法确认持久化时，当前进程停止重建和使用旧密钥；重启后，已知不匹配身份也不能用于推送解密或快照恢复。如果上次显示持久化失败留下旧 catalog，启动恢复还必须退休已加载的无效显示，而不只是拒绝从 binding 再发布一次；有效的其他实例保持不变。临时读不到 ledger 不等同于已确认身份失效。存储故障需要先恢复存储可用性，不承诺故障期间自动修复成功。

退出登录、显式禁用和普通的项目/部署退休会撤销修复意图；维护在控制锁内重新检查意图，避免此前捕获的任务在禁用后重新创建。成功保存新绑定会消费意图。测试使用本地存储与 HTTP/display fixture，不代表执行过真实 APNs 投递或设备迁移。

APNs 配置页把网络/服务端读取失败与“成功读取但没有配置”分开显示，并提供刷新操作。读取失败时不要据此重建或轮换密钥。

## Mac 公证上传预算

`MAC_NOTARY_UPLOAD_TIMEOUT` 只控制 Mac 公证 ZIP/DMG 的上传子进程，单位为秒，默认 `1800`。值必须是正有限数值；空值、零、负数、非数字、NaN 和 Infinity 都被拒绝。普通查询和预检命令仍使用 120 秒预算。

慢链路可在启动或恢复发布前增大该环境变量。它不属于签名产物身份，调整后不要求仅因超时配置重建产物；但它也不是 Apple 处理时限，更不是整批发布完成的保证。

上传超时仍可能留下无法确认 submission ID 的状态。此时保留 checkpoint，先核对 Apple 历史记录；普通 resume 不盲目重传，`--resubmit-unknown` 仍需要操作员明确授权。已有 ID 的查询超时保留该 ID。不要通过手写成功 manifest 或修改已签名 App 来恢复。

## 验证边界

回归验证使用本地桩、隔离数据和假发布器；不以真实 Apple 上传、签名凭据或生产迁移作为自动测试。本文不是这些远程操作已成功执行的证明。稳定版本契约和正式发布说明仍需在对应修复发布时更新。
