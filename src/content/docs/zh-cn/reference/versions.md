# 版本、来源与兼容性

版本号、Git 提交与构建产物回答**不同的问题**。使用命令、修改部署或解释
示例响应前,核对相关身份——不要只看一个版本字符串。

## 本版手册的基线

| 表面 | 基线 | 能说明什么 |
| --- | --- | --- |
| 服务端与 CLI | `1.1.0`,发布源码 `fd340879076a87c2662c454788178eecb05d0036` | 稳定页针对的**已发布**产品行为 |
| 已核验 main 源码 | `03751a679ed0205505ab9fae5207a66189c47a18` | 文档契约核验所依据的源码(含后续发布工具工作);main **不等于**另一个已发布服务端镜像 |
| 原生客户端 | `0.1.0`,独立版本线 | 应用的 marketing version——**不表示**服务端或附带 CLI 也是 0.1.0;build number、架构、分发渠道同样重要 |
| 文档 | `contracts/manifest.json` | 手册版本、核验/发布源码、契约摘要、dirty/candidate 状态与发布就绪状态 |
| APNs Widget 快照 | 尚未发布的预览工作,不属于 server 1.1.0 | **不能**作为稳定版安装前提,也不能承诺为稳定版内网刷新路径 |

新文档在覆盖与验收门槛通过前仍是**重建预览**。页面标为 `channel: stable`
表示描述的是已发布能力——**不代表**整套新手册已完成正式发布。同样,
**不能**只为通过部署检查,就把 `source_dirty: true`、
`review_status: candidate` 改成"干净且已审阅"的导出。

## 检查已安装组件

```sh
viat --version
viat version
```

- `--version` 只查本地;`version` 还会尝试读已登录服务端经认证的
  `/version`。本地成功**不证明**服务端网络或认证有效。服务端响应形状:

```json
{"version":"1.1.0"}
```

  这是目标发行版的示意响应——**不保证**当前所选实例就是该版本。
  `/healthz` 刻意不暴露版本:探针成功**推断不出**发行身份。具体输出与
  错误行为见 [CLI 通用命令](../cli/utilities.md)。
- 原生产物应与随附发布元数据、摘要共同保存;核对应用版本、build
  number、架构/渠道与附带 CLI 版本。iOS 开发设备产物、注册设备分发、
  App Store Connect 产物的签名与安装要求各不相同——**重命名文件改变
  不了分发渠道**。

## 兼容性规则

- 使用**运行中服务端**对应的手册版本,而不只是网站最新页面。
- 本地测试宿主协议要求 CLI、`viat-test-host`、
  `viat-endpoint-test-host` **互相匹配**;仅装 CLI 不会装 Python、Bun
  或 Rust 构建工具链。
- 资源 schema 描述结构,**不涵盖**全部条件 API 规则;当前源码支持某
  类型,不证明较旧的运行服务端支持它。
- 管理 API/控制台类型与项目端点 OpenAPI 是**不同契约**;生成的端点
  OpenAPI 不描述整个管理 API。
- Cargo 版本仍是 1.1.0 的检出可能已含未发布变更——用新行为前核对提交
  与产物来源。
- 端点快照固定端点/目标状态,**不固定**所有外部依赖或凭据;工作流步骤
  的 `uses:` 有实时解析例外,见[核心概念](../overview/concepts.md)。
- 重建或回滚端点**不回滚**数据库迁移、外部系统、资源凭据或共享实时
  依赖。

## 更新契约与文档

维护者从明确选择的产品检出导出契约,以 candidate 导入 → 审阅差异 →
同步两种语言 → 重跑示例。资源、语言清单、CLI 叶命令与 MCP 工具有覆盖
检查——但检查**不替代**行为审阅或提供商/设备验收。

每页原始 Markdown 带相同版本/通道信息;稳定 LLM 索引**不含**预览能力页。
离线书从同一份 Markdown 生成;替换随产品携带的书之前必须固定为已验收的
文档产物——**不是**启动时从最新网站抓取。

## 版本不一致时

| 现象 | 处理 |
| --- | --- |
| CLI 比服务端新 | 查**服务端**对应的手册并验证所需命令/API;不假定新字段向后兼容 |
| 本地测试 host 报另一版本 | 换成与 CLI 匹配的 host——不绕过握手 |
| 原生应用能用,但某功能缺失 | 核对平台、构建/渠道与服务端能力;应用 marketing version 不足以判断 |
| main 有某功能,发行产物没有 | 保持**预览**标识,直到匹配产物真正发布 |
| 文档 build 成功,release check 失败 | 查覆盖/证据缺口;预览成功不是把 manifest 标为 ready 的理由 |

本页记录来源,**不执行升级**。真实升级前按
[安装说明](../installation/docker-compose.md)备份部署状态并验证恢复。
**不要**仅因文档示例提到更新提交,就修改 DNS、发布产物或替换运行服务。
