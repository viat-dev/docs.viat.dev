# 配置模型与完整索引

本手册描述稳定版 **1.1.0**。本页帮你回答三个问题:配置放在哪里、谁有权
改、改完如何验证。各专题(数据库/安全/运行时/网络/存储/观测/集成)的
完整变量表从下面的索引进入。

> [!WARNING]
> 配置与运维章节中的所有命令都是**待运维审阅的模板,编写文档时未执行**。
> 替换示例名称与凭据、确认副作用、先在隔离环境验证,再用于生产。
> 首次部署请先读 [Docker Compose 安装](../installation/docker-compose.md)
> 或[二进制与源码安装](../installation/binary-source.md)。

## 配置入口

| 入口 | 操作者 | 持久性与优先级 |
| --- | --- | --- |
| 进程环境变量 | 主机/容器运维 | 服务端没有通用 YAML 配置文件,也没有统一的重载 API。显式进程/容器环境覆盖镜像 `ENV`;未设置时用下表实际运行时默认值;修改后重启或重建容器。 |
| 镜像与容器 | Docker 管理员 | 镜像提供解释器、静态文件与部分默认值。Compose `.env` 只做变量替换,**不会自动注入进程**——服务的 `environment` 等入口必须显式传入。 |
| 部署包装脚本 | 主机运维 | `deploy-server.sh` 把 `.env` 当 **shell 脚本**加载而非被动 dotenv——只能使用可信文件;脚本变量 ≠ 应用配置,见[网络配置](network.md)。 |
| 实例设置 | 平台 Owner/Admin | 存 PostgreSQL;不能代替数据库连接、主密钥、监听或工作进程配置。 |
| 项目、端点、资源 | 有相应权限的项目成员 | 草稿 ≠ 已发布快照;端点认证/绑定/覆盖通常要发布才生效,草稿测试成功不代表路由变了。 |
| CLI/MCP 会话 | 本地客户端用户 | `.viat/config.yaml` 与客户端环境,不是服务端参数,见[集成配置](integrations.md)。 |

> [!NOTE]
> 布尔值**没有统一解析规则**:有的开关只认小写 `false`/`0`,有的接受
> 大小写不敏感的 `no`,有的启用开关必须严格写 `1`。安全开关拼错后,
> 功能可能仍然开启——改完务必验证。

## 变量表的统一约定

每项说明**类型、二进制实际默认值、单位/范围、校验与回退、作用域和覆盖
关系**。除标注**必填**外均可选。没有特别说明时:合法显式值替换运行时
默认值;数字解析失败用列出的默认值;"未设置"不等于空字符串。`u64`/`u32`/
`u16`/`usize`/`i64` 用相应 Rust 整数范围(`usize` 随平台位数);表中列出的
是额外产品约束——**不要把理论最大值当可运维值**。

作用域与重载代码:

| 代码 | 含义 |
| --- | --- |
| **S** | 启动或构建路由时读取,须重启。 |
| **F** | 首次使用后进程内缓存,须重启。 |
| **D** | 执行相关操作时读取;没有从外部修改运行进程环境的通用机制——修改部署配置后仍需重启,**编辑 `.env` 不会热加载**。 |
| **W** | 创建工作进程/编译进程时读取;现存进程不变;改后重启并重建相关环境。 |
| **C** | CLI/MCP 本次调用,不作用于服务端;重跑客户端。 |
| **I** | 安装脚本、Compose 或镜像构建输入,不是服务端参数;确认副作用后重新部署/构建。 |

只有明确注明时,项目或脚本才可覆盖;端点作者不能突破部署上限。执行超时
按"目标声明 → 项目默认 → 部署默认"选择,再受同步/异步上限约束;构建预算
与代理超时是另一套参数。

## 修改、验证与恢复

1. 记录当前版本、镜像摘要、部署文件、挂载与变更原因;**不要把密钥值写入
   工单或进程命令行**。
2. 核对该项的 Docker/二进制差异与单节点/共享作用域;多节点的密钥、公共
   URL 和后端选择应一致。
3. 迁移、换密钥/后端或缩短保留期之前,按[备份恢复](../operations/backup-restore.md)
   完成备份——直接替换主密钥不是轮换流程。
4. 修改**服务实际环境**:Compose `.env` 加一行而不传入服务不会生效;系统
   服务用服务管理器的环境配置;二进制自身不加载 `.env`。
5. 优雅重启并检查启动日志:启动会创建上限 10 条连接的平台数据库池、执行
   内置迁移、按需创建初始 Owner、初始化后端并启动后台循环,然后开始服务。
6. 检查 `/healthz`、`/readyz`、需认证的 `/version`、登录与隔离项目请求
   ——探针正常**不代表**激活、依赖、外部凭据或通知投递正常。
7. 出问题可恢复上一组非破坏性配置再重启;数据库迁移回滚与被删数据必须走
   恢复流程,不能只换回旧镜像。

## 运行时默认值 ≠ Docker 默认值

二进制未配置时允许注册;官方镜像设 `VIAT_ALLOW_REGISTRATION=false`。镜像
另设 `VIAT_WEB_DIR=/app/web`、`VIAT_DOCS_DIR=/app/docs`、
`VIAT_BIND=0.0.0.0:8080`、`VIAT_SHELL_BIN=/bin/bash`、
`SCHEDULER_ENABLED=true`、`RUST_LOG=info`、`HOME=/home/viat`;`-build`
镜像再加 Rust SDK、产物、目标目录与 Cargo/rustup 路径。普通镜像不含 Rust
编译器——即使二进制构建开关默认打开。部署示例中的 `4g` 内存与 `512` PID
限制是**容器示例,不是应用默认容量,也不是性能实测**。
