# Viat 是什么

Viat 是可自行部署、以端点为中心的 API 平台。你的工作循环是:**建项目 →
写脚本/工作流 → 绑定到 HTTP 路径 → 发布**。平台负责接收请求、识别调用者、
绑定输入、执行目标并记录结果。

一句话理解核心机制:**脚本本身不会自动成为 API——发布端点才是把接口契约
交给调用者的那一步**;此后外部流量读取的是不可变的已发布快照,不是你的
草稿。

版本基线:本手册的稳定基线是 server/CLI **1.1.0**;原生客户端是独立的
**0.1** 版本线。源码检出、客户端构建与已发布服务端镜像不是同一类产物;
尚未发布的加密 APNs Widget 快照不属于这个稳定基线。

## 工作模型

1. **实例**:一套部署——PostgreSQL 平台数据库、认证配置、激活状态、一个或
   多个服务进程。
2. **项目**:协作与 API 的命名空间;slug 出现在 `/p/hello-lab/hello` 这样的
   对外路径里。
3. **资产**:脚本、工作流、资源、认证器、端点树,都属于项目。
4. **端点草稿**:可编辑的路径、方法、目标、输入与认证/授权设置;编辑不会
   立即改变已发布 API。
5. **已发布快照**:请求分发实际使用的版本,不是"最新的端点行"。
6. **执行**:一次请求或触发运行及其日志——与编辑、发布是三件不同的事。

设计共享认证或回滚流程前,先读[核心概念](concepts.md)。

## 一次请求如何流转

以 `POST /p/hello-lab/hello` 为例:

1. Viat 在项目中选择**已发布**的路由,并核对 HTTP 方法。
2. 路由允许的认证器识别调用者;授权门禁决定能否继续。
3. 按端点契约,把路径、查询参数与请求体绑定为目标的输入。
4. 脚本、工作流、代理、CRUD 或 WebSocket 目标走各自的执行路径。
5. Viat 返回结果并记录执行信息——被拒绝的请求也有执行记录,**出现记录不
   代表脚本运行过**。

所以,一个返回 JSON 的 Python 函数不需要另写 HTTP 服务就能成为接口;但输入
结构、授权规则、上游错误处理、业务写入幂等性仍然是你的责任。

## 凭据与数据放在哪里

- 平台数据库是 **PostgreSQL**。`sqlite` 资源是应用数据连接:不是可替换的
  平台数据库,也不代表独立的桌面本地模式。
- 资源连接凭据由平台保存,并在平台执行资源操作时应用。不要让脚本依赖获取
  原始数据库密码、私钥或上游认证请求头;秘密值资源与配置各有明确语义——
  不要把凭据写进非秘密的 `plain` 配置或日志。
- **主密钥要与数据库分开备份**:丢失主密钥可能使加密的资源凭据无法使用。
- 1.1.0 的部分旧式脚本资源投影仍可能携带连接凭据(详见[概念](concepts.md)
  与各资源参考);管理 API 脱敏不证明所有脚本视图都不含凭据。
- 脚本是可执行代码:工作进程账号隔离、超时与容器限制是有用的防护,但不等
  于面向恶意租户的隔离承诺。给脚本编写者与上游服务账号都分配最小权限。

## 安全的首次检查

对获准使用的实例,读存活探针:

```sh
curl --fail --silent --show-error http://127.0.0.1:8080/healthz
```

预期响应体:

```json
{"status":"ok"}
```

这只能证明 HTTP 正在服务,**不能**证明实例已激活、数据库就绪或某个项目
存在。登录后用 `viat version` 查看 CLI 与服务端版本;完整登录步骤见
[第一个端点](../getting-started/first-endpoint.md)。

## 限制与常见误区

| 现象 | 真相与处理 |
| --- | --- |
| `403 license_required` | 进程可以健康,但受保护路由仍锁定;按[激活](../instance/activation.md)处理,不要反复重启 |
| 项目列表为空 | 平台账号 ≠ 项目成员;请项目 Owner/Admin 把账号加进项目 |
| 草稿测试成功,HTTP 仍返回旧结果 | 编辑后需要发布;普通 `uses:` 依赖发布时冻结,`(live)` 依赖与草稿测试行为不同 |
| 上游连接失败 | 检查资源与**服务端**的网络路径;笔记本能访问内网不代表容器能 |
| 客户端 Widget 时间戳较旧 | 缓存状态不是实时监控连接;刷新时机由操作系统控制 |

[能力地图](capabilities.md)帮你选操作入口。首次实验请使用
[第一个端点](../getting-started/first-endpoint.md)的独立项目,完成后取消
发布并删除端点/脚本;不要覆盖其他项目的路由。
